BOORU IMAGE SHARING APP — WORKFLOW

PROJECT STACK

* Frontend: Next.js / React
* Backend: ElysiaJS + Bun
* Authentication: Supabase Auth
* Database: Supabase PostgreSQL
* Image Storage: Supabase Storage

==================================================

1. USER TYPES
   ==================================================

Anonymous User

* Can view images
* Can search images
* Cannot upload
* Cannot edit
* Cannot delete

Registered User

* Can view images
* Can search images
* Can upload images
* Can edit their own images
* Can delete their own images

Admin

* Can view images
* Can search images
* Can upload images
* Can edit images
* Can delete any image

6. IMAGE STORAGE WORKFLOW
=========================

The actual image file is stored in:

Supabase Storage

Example:

images/
├── 123-cat.jpg
├── 124-dog.jpg
├── 125-landscape.jpg
└── ...

PostgreSQL stores only metadata:

## images

id
filename
url
tags
uploaded_by
created_at

The database does NOT need to store the actual image binary.

13. AUTHORIZATION LOGIC
=======================

When accessing a protected endpoint:

Request
|
v
Does JWT exist?
|
+---- NO ----> 401 Unauthorized
|
v
Verify JWT
|
+---- Invalid ----> 401 Unauthorized
|
v
Get current user
|
v
Check permission
|
+---- Not allowed ----> 403 Forbidden
|
v
Perform action

For deleting an image:

if user is not authenticated:
return 401

if user.role == "admin":
allow

else if image.uploaded_by == user.id:
allow

else:
return 403

16. SIMPLE MVP SCOPE
====================

FIRST VERSION SHOULD ONLY HAVE:

1. Registration / Login
2. Image upload
3. Image gallery
4. Image detail page
5. Tags
6. Search by tags
7. Delete own images
8. Admin role
9. Admin delete
10. Supabase Storage

Do NOT add initially:

* Redis
* WebSockets
* Microservices
* Image processing workers
* Complex recommendation systems
* Multiple databases
* Elasticsearch

Start with:

Next.js/React
+
ElysiaJS + Bun
+
Supabase Auth
+
Supabase PostgreSQL
+
Supabase Storage
